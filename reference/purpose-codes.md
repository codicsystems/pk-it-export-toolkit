# Purpose codes on inbound remittances

The most consequential detail in Pakistani IT exporting is a code typed by a
bank officer you will never meet.

---

## What a purpose code is

When foreign currency arrives in Pakistan, the receiving bank assigns a code
classifying what the money is for. The code determines how the receipt is
reported to the State Bank, whether withholding is applied at realisation, and
whether the money is documented as **export income** or as a **personal
transfer**.

IT and IT-enabled services exports have their own code. Family remittances and
gifts have a different one.

## Why the wrong code costs you

Suppose a UK client pays you USD 8,000 and the bank codes it as a home
remittance rather than an IT services export.

**No withholding is applied.** This feels like a win. It is not.

**Your income was never recorded as export income.** The concessional regime for
IT exports operates through the bank withholding at the moment proceeds are
realised under the IT services code. If that did not happen because the code was
wrong, you are arguing for the treatment at assessment rather than evidencing
it, and the burden is yours.

**The payment does not count toward IT export turnover.** That matters at PSEB
renewal, where turnover is verified, and for any facility that depends on export
volume.

**The pattern draws attention.** A business account receiving substantial,
regular, round-number inflows from foreign companies, all coded as family gifts,
is exactly the shape that monitoring systems are built to surface.

## How often this happens

Often enough that checking every remittance is the standard practitioner habit
rather than a precaution. Pakistani IT exporters have reported through 2026 that
banks default to the personal remittance code and that the problem recurs across
multiple institutions. Branch staff who process one IT export a year will code
it the way they code everything else.

The State Bank's 2026 reforms for IT exporters address this directly: a one-time
declaration of the nature of services replaces per-transaction documentation,
and banks tag the relevant service and purpose code against the exporter's
account rather than deciding per credit. That is a real improvement — but it
only works if you file the declaration, and implementation across branches has
been uneven.

---

## The three-step discipline

### 1. Declare once, at the account

File the [purpose code declaration](../templates/purpose-code-declaration.md) on
company letterhead, at the branch, before your first client payment. Get it
stamped as received. Get the name and direct number of the officer who handles
foreign remittances.

### 2. Instruct on every invoice

Put a line on the invoice itself:

> *Please instruct your bank to remit this payment as payment for information
> technology services.*

This puts the right words in the sending bank's reference field, which is what
your bank's remittance desk reads when deciding how to code the credit. It costs
one line and it is the cheapest insurance on the document.

### 3. Check every single credit advice

Every payment. Every time. Within the week.

If the code is wrong, call the branch immediately, reference your declaration,
and have it corrected. **Corrections within days are administrative. Corrections
within months are a negotiation.**

---

## When the branch will not fix it

Escalate rather than repeating yourself at the counter.

1. Ask the branch to refer it to their **trade finance or remittance desk** at
   head office. Branch staff frequently do not know the current procedure;
   the specialist desk does.
2. Banks are required to operate an internal complaint mechanism for IT
   companies and freelancers. **Use it in writing**, and reference your filed
   declaration and the date it was received.
3. If a designated branch repeatedly miscodes, move. Trade bodies publish lists
   of bank branches and focal officers set up to facilitate the IT sector.
   Starting at a branch that processes these weekly is very different from
   starting at one that has never seen an export receipt.

---

## The certificate

Separately from the code, ask for the **Proceeds Realisation Certificate** —
issued by some banks as an Inward Remittance Certificate — for every export
receipt. It certifies the amount, the date of realisation and the purpose code
applied.

Many banks generate it automatically. Many will not tell you. Some will not
issue one unless you ask by name. Ask by name, and include the request in your
declaration letter so it is on file from the start.

The PRC is your proof of export income for tax assessment, for PSEB renewal
turnover verification, and for visa applications — where a genuine trading
income is exactly what is being assessed and a Pakistani company's PRCs are
among the strongest supporting documents you can file.
